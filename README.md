# QA Agentic Framework

An AI-driven QA pipeline. You upload a requirement (for example a Jira story) in a web page, and Claude agents take it from there:

requirement analysis → test cases → Playwright scenarios → independent review → automation → execution → failure analysis → Jira defects → release-readiness report.

| Folder | What it holds |
|---|---|
| `.claude/agents/` | One file per agent (instructions, tools, model) |
| `AgentUI/` | The web page and the Node server that runs the agents |
| `TestAutomate/` | The Playwright suite (Page Object Model) that the agents extend |
| `Requirement/` | Uploaded requirements |
| `TestCases/`, `TestDesign/`, `TestReview/`, `TestResults/`, `FailureAnalysis/`, `ReleaseReadiness/`, `PipelineReports/` | Pipeline output. Generated on the host and not stored in Git |
| `deploy/` | Scripts that keep the UI running on a server |

## Requirements

- Node.js 22.9 or later
- Git (on Windows, Git for Windows, which includes the Git Bash the agents use)
- Access to Claude: a company Anthropic API key, or Claude through Microsoft Foundry
- A Jira Cloud API token, used to file defects

Outbound HTTPS is needed to `api.anthropic.com` (or your Foundry endpoint), the application under test (`www.saucedemo.com`), your Jira site, `registry.npmjs.org`, and the Playwright browser download hosts (`cdn.playwright.dev`, `playwright.download.prss.microsoft.com`) during setup.

## Set up a host (Azure VM or a laptop)

```bash
git clone <gitlab-url>/qa-agentic-framework.git
cd qa-agentic-framework

cp .env.example .env            # Windows: copy .env.example .env
# fill in .env: Claude credentials, Jira, UI_PASSWORD, PLAYWRIGHT_HEADED

cd TestAutomate
npm ci
npx playwright install --with-deps   # Windows: npx playwright install
cd ../AgentUI
npm ci
npm start
```

Open `http://<host>:4000` and sign in with `UI_PASSWORD` (leave the user name empty).

### Behind a corporate proxy

Set `HTTPS_PROXY` and `NO_PROXY` in `.env` for the server and agents. For setup commands, set them in the shell too, plus `npm config set proxy …` / `https-proxy …`. If outbound HTTPS is TLS-inspected, point `NODE_EXTRA_CA_CERTS` at the company root certificate (PEM).

### Headed or headless

By default the tests open visible browser windows. That needs a logged-in desktop session:

- **Windows VM with a desktop session:** create a local service account, turn on auto-logon for it, and keep `PLAYWRIGHT_HEADED=true`.
- **Linux VM, or Windows without auto-logon:** set `PLAYWRIGHT_HEADED=false`. The agents then run Playwright headless.

## Keep it running

**Windows:** from an elevated PowerShell, in the repository folder:

```powershell
.\deploy\windows\install-task.ps1 -User 'VM\qa-runner'             # headed: starts at that user's logon
.\deploy\windows\install-task.ps1 -User 'VM\qa-runner' -Headless   # starts at boot
```

The log goes to `AgentUI\server.log`.

**Linux:** see the instructions at the top of [deploy/linux/qa-agent-ui.service](deploy/linux/qa-agent-ui.service). Logs are in `journalctl -u qa-agent-ui`.

## Access

The UI listens on `PORT` (default 4000) on every network interface. Keep it on the internal network or VPN, or put it behind a reverse proxy with company single sign-on. Never expose it directly to the internet: the agents can run commands on the host, and the UI's only protection is a single shared password.

## Updating the host from GitLab

The pipeline writes new and updated test scripts into `TestAutomate/` on the host. Before pulling, commit those back so nothing is lost:

```bash
git checkout -b pipeline/<date>
git add TestAutomate Requirement
git commit -m "Tests generated by the pipeline"
git push -u origin pipeline/<date>      # then open a merge request
git checkout main && git pull
```

Then restart the UI: run the scheduled task again on Windows, or `sudo systemctl restart qa-agent-ui` on Linux.

## CI

[.gitlab-ci.yml](.gitlab-ci.yml) checks on every push that dependencies install, the Playwright suite still loads and the server's code parses. It doesn't run the tests themselves.

## Running the agents from Claude Code

Without the UI, open the folder in Claude Code and ask, for example, "run the whole pipeline for Requirement/JIRA-190.txt with parent issue SCRUM-1". The orchestration-agent then runs every stage.
